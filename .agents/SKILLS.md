# SKILLS.md — Інструкції та операційні навички агентів

У цьому файлі зафіксовано правила, контекстні стандарти, моделі даних та інженерні патерни, яких агенти зобов'язані суворо дотримуватися під час написання коду й конфігурацій проєкту.

---

## 1. Схема бази даних SQLite

Агенти повинні використовувати таку структуру таблиць та індексів під час ініціалізації бази:

```sql
-- Таблиця конфігурації та системних параметрів
CREATE TABLE IF NOT EXISTS settings (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL
);

-- Таблиця звичок
CREATE TABLE IF NOT EXISTS habits (
    id TEXT PRIMARY KEY,
    title TEXT NOT NULL,
    description TEXT,
    icon_name TEXT NOT NULL,
    color_hex TEXT NOT NULL,
    target_type TEXT NOT NULL DEFAULT 'binary', -- 'binary' (так/ні) або 'numeric' (числовий прогрес)
    target_value INTEGER DEFAULT 1,             -- Ціль (наприклад: 8 склянок, 20 сторінок)
    unit_label TEXT,                            -- Назва одиниці ('склянок', 'хвилин', 'сторінок')
    position INTEGER NOT NULL DEFAULT 0,        -- Порядковий номер для сортування
    is_archived INTEGER NOT NULL DEFAULT 0,     -- М'яке видалення (1 = архівована)
    created_at TEXT NOT NULL                    -- Формат ISO: YYYY-MM-DDTHH:MM:SSZ
);

-- Журнал щоденних позначок виконання
CREATE TABLE IF NOT EXISTS habit_logs (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    habit_id TEXT NOT NULL,
    log_date TEXT NOT NULL,                     -- Дата виконання у форматі YYYY-MM-DD
    current_value INTEGER NOT NULL DEFAULT 1,   -- Фактично виконане значення
    is_completed INTEGER NOT NULL DEFAULT 1,    -- 1, якщо ціль досягнуто повністю
    updated_at TEXT NOT NULL,                   -- Формат ISO: YYYY-MM-DDTHH:MM:SSZ
    UNIQUE(habit_id, log_date),
    FOREIGN KEY(habit_id) REFERENCES habits(id) ON DELETE CASCADE
);

-- Індекси для оптимізації швидких вибірок
CREATE INDEX IF NOT EXISTS idx_habit_logs_date ON habit_logs(log_date);
CREATE INDEX IF NOT EXISTS idx_habit_logs_habit ON habit_logs(habit_id);
CREATE INDEX IF NOT EXISTS idx_habits_active ON habits(is_archived, position);

```

## 2. Стандарти локалізації та правил обчислення часу (uk-UA)

* **Дні тижня:**
* Тиждень суворо починається з **понеділка**.
* Повні назви: `Понеділок`, `Вівторок`, `Середа`, `Четвер`, `П'ятниця`, `Субота`, `Неділя`.
* Скорочення для інтерфейсу: `Пн`, `Вт`, `Ср`, `Чт`, `Пт`, `Сб`, `Нд`.
* Однобуквені позначки для круглих кнопок тижня: `П`, `В`, `С`, `Ч`, `П`, `С`, `Н`.


* **Правила української плюралізації (Intl / i18n):**
* `one` (закінчується на 1, крім 11): *1 звичка, 21 звичка, 101 день*.
* `few` (закінчується на 2–4, крім 12–14): *2 звички, 4 дні, 33 відсотки*.
* `many` / `other` (все інше, включаючи 0 і числа 11–14): *0 звичок, 5 звичок, 11 днів*.


* **Зсув доби (Day Rollover / Cutoff Time):**
* Для користувачів, які лягають спати після опівночі, зміна поточної дати `log_date` має враховувати налаштування зсуву (за замовчуванням `03:00` або `04:00`).
* Будь-які дії до настання години зсуву записуються в попередній календарний день.

## 3. Специфікація інтерфейсних компонентів та стилів

* **Колірна схема (Deep Dark Palette):**
* Основне тло вікна: `#0B0C10` або `#0F1015`.
* Тло карток і контейнерів: `#16181F` зі скругленням `rounded-2xl` (16px).
* Межі (Borders): `border border-white/5` або `border-white/10`.
* Текст: основний `#FFFFFF`, приглушений `#9CA3AF`, другорядні підписи `#6B7280`.


* **Специфікація теплової карти (Activity Heatmap):**
* Структура: CSS Grid із 7 рядків (дні тижня) і 52 колонок (тижні року).
* Розмір кожної комірки: `10px × 10px`, відступи `gap-[3px]`, скруглення `rounded-[2px]`.
* Градація кольорів за відсотком виконання від усіх активних звичок за день:
* `0%` виконано: `#1A1D24`
* `1% – 25%`: `#0E4429`
* `26% – 50%`: `#006D32`
* `51% – 75%`: `#26A641`
* `76% – 100%`: `#39D353`


* Інтерактивність: обов'язковий спливаючий tooltip при наведенні курсора з точною датою та кількістю закритих цілей (наприклад: *«14 серпня 2026: 4 з 5 звичок виконано»*).


* **Рядок звички (Habit Item Row):**
* Кожна звичка має свій закріплений акцентний колір (бірюзовий, ультрамариновий, бузковий, янтарний, кораловий).
* Іконка відображається всередині кола з фоном `bg-[color]/15` і контуром кольору `text-[color]`.
* Коло дня тижня:
* Невиконано: порожній контурний кружок `border border-white/20`.
* Виконано: суцільна заливка кольором звички з білою або контрастною галочкою (іконка `Check`).
* Натискання: обов'язковий мікро-фідбек `active:scale-95 transition-transform duration-100`.

## 4. Архітектурні патерни Tauri 2 та фонової роботи

* **Безрамкове вікно (Frameless Window):**
* У `tauri.conf.json` задається `decorations: false`.
* Угорі інтерфейсу виділяється область перетягування вікна за допомогою HTML-атрибута `data-tauri-drag-region`.


* **Поведінка системного трея:**
* Подія закриття вікна (`WindowEvent::CloseRequested`) завжди блокується через `api.prevent_close()`, викликаючи приховання `window.hide()`.
* Одинарний клік лівою кнопкою миші по іконці в системному треї перемикає стан: показує та фокусує вікно або ховає його.
* Контекстне меню трея містить лише необхідні пункти українською мовою: *«Відкрити»*, *«Налаштування»*, *«Вийти»*.


* **Фонова зміна дня (Midnight Daemon):**
* Фоновий таймер на стороні Rust або фронтенду кожну хвилину перевіряє факт переходу через встановлений час доби.
* У момент настання нового дня ініціюється внутрішня подія `emit("day-changed")`, яка змушує інтерфейс перерахувати сьогоднішній стовпчик без перезавантаження сторінки.


* **Принцип оптимістичного інтерфейсу (Optimistic UI):**
* При кліку на чекбокс стан змінюється у фронтенд-сторі миттєво.
* Команда запису в SQLite виконується асинхронно у фоні. Якщо операція бази завершується помилкою, стан повертається назад з показом toast-сповіщення.
